1Executive Summary

What Nexus is, and the problem it solves.

Modern software development increasingly happens alongside AI assistants. Yet every new chat session starts from zero: the developer re-explains the architecture, the decisions already made, the current task, and the constraints. Athreix Nexus eliminates that repetition. It maintains a durable, structured memory of a project on disk and reconstructs a complete continuation context on demand.

Local & Offline

Zero network calls. All memory lives in a .nexus/ folder beside your code.

Universal Handoff

Generates context compatible with Claude, ChatGPT, Gemini, Cursor, Windsurf and open agents.

Structured Memory

Decisions, architecture, timeline, tasks, and a knowledge graph — not free-form notes.

Fast & Portable

Single optimized Rust binary (~10 MB), SQLite + JSON storage, cross-platform.

Technology Stack

Rust 2021 clap rusqlite + FTS5 tree-sitter git2 serde / serde_json rayon chrono uuid sha2

Tree-sitter grammars: Rust, JavaScript, TypeScript, Python. Release profile uses LTO, a single codegen unit, and symbol stripping for a compact binary.

Typical workflow

# 1. Initialize and analyze
nexus init
nexus scan

# 2. Record knowledge as you work
nexus decide "Use SQLite for offline-first local storage" --rationale "no server dependency"
nexus decide "Use Postgres for the API" --supersedes 9b353bf8

# 3. Reconstruct context for an AI assistant
nexus continue --task "implement the search index"
nexus continue --compress --max-tokens 4000 --output context.txt
nexus handoff --output handoff.xml

# 4. Explore & maintain
nexus impact db.rs
nexus ask "authentication flow"
nexus map
nexus health
nexus snapshot "before-refactor" --description "stable checkpoint"
nexus restore before-refactor

6Data & Persistence

Nexus uses dual persistence: human-readable JSON for portability and inspection, and SQLite for indexed querying.

SQLite (knowledge.db)

  • Tables: decisions, tasks, timeline_events, knowledge_nodes, knowledge_edges, sessions, snapshots, scan_history, schema_meta.
  • Full-text search: an FTS5 virtual table (memory_fts) with the porter tokenizer powers nexus ask and the --task ranking.
  • Durability: WAL journal mode, synchronous=NORMAL, a 5-second busy timeout, and enforced foreign keys.

JSON stores

  • memory.json, architecture.json, timeline.json, decisions.json, tasks.json plus per-file session records.
  • Atomic writes: every JSON write goes to a temp file, is flushed and fsynced, then atomically renamed over the target — a crash mid-write cannot corrupt memory.

7NXP — Nexus Protocol

The Nexus Protocol (NXP) is a portable, self-describing document that captures the full state of a project's memory — identity, architecture, decisions, tasks, timeline, knowledge graph, recent AI sessions, and a git summary — for transfer between machines, teammates, or tools.

  • nexus export writes .nexus/project.nxp.
  • nexus import [--file <path>] ingests an NXP document.
  • Current protocol version: 1.0.0. The handoff envelope is versioned and XML-escaped for safe embedding in any AI client.

9Build, Test & Install

Build

# Debug build
cargo build --workspace

# Optimized release binary (~10 MB, LTO + stripped)
cargo build --release --workspace

Test & lint

cargo test  --workspace
cargo clippy --workspace -- -D warnings
cargo fmt --all -- --check

Install

# Put the `nexus` binary on your PATH
cargo install --path crates/nexus-cli

# Verify
nexus --version
nexus --help
